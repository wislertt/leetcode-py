## Problem

&lt;p>Every valid email consists of a local name and a domain name, separated by the &lt;code>&#39;@&#39;&lt;/code> sign. Besides lowercase letters, the email may contain one or more &lt;code>&#39;.&#39;&lt;/code> or &lt;code>&#39;+&#39;&lt;/code>.&lt;/p>

&lt;ul>
	&lt;li>For example, in &lt;code>&quot;alice@leetcode.com&quot;&lt;/code>, &lt;code>&quot;alice&quot;&lt;/code> is the &lt;strong>local name&lt;/strong>, and &lt;code>&quot;leetcode.com&quot;&lt;/code> is the &lt;strong>domain name&lt;/strong>.&lt;/li>
&lt;/ul>

&lt;p>If you add periods &lt;code>&#39;.&#39;&lt;/code> between some characters in the &lt;strong>local name&lt;/strong> part of an email address, mail sent there will be forwarded to the same address without dots in the local name. Note that this rule &lt;strong>does not apply&lt;/strong> to domain names.&lt;/p>

&lt;ul>
	&lt;li>For example, &lt;code>&quot;alice.z@leetcode.com&quot;&lt;/code> and &lt;code>&quot;alicez@leetcode.com&quot;&lt;/code> forward to the same email address.&lt;/li>
&lt;/ul>

&lt;p>If you add a plus &lt;code>&#39;+&#39;&lt;/code> in the &lt;strong>local name&lt;/strong>, everything after the first plus sign will be &lt;strong>ignored&lt;/strong>. This allows certain emails to be filtered. Note that this rule &lt;strong>does not apply&lt;/strong> to domain names.&lt;/p>

&lt;ul>
	&lt;li>For example, &lt;code>&quot;m.y+name@email.com&quot;&lt;/code> will be forwarded to &lt;code>&quot;my@email.com&quot;&lt;/code>.&lt;/li>
&lt;/ul>

&lt;p>It is possible to use both of these rules at the same time.&lt;/p>

&lt;p>Given an array of strings &lt;code>emails&lt;/code> where we send one email to each &lt;code>emails[i]&lt;/code>, return &lt;em>the number of different addresses that actually receive mails&lt;/em>.&lt;/p>

### Examples

```
Input: emails = ["test.email+alex@leetcode.com","test.e.mail+bob.cathy@leetcode.com","testemail+david@lee.tcode.com"]
Output: 2
Explanation: "testemail@leetcode.com" and "testemail@lee.tcode.com" actually receive mails.
```

```
Input: emails = ["a@leetcode.com","b@leetcode.com","c@leetcode.com"]
Output: 3
Explanation: All three addresses actually receive mails.
```

### Constraints

- 1 &lt;= emails.length &lt;= 100
- 1 &lt;= emails[i].length &lt;= 100
- emails[i] consist of lowercase English letters, &#39;+&#39;, &#39;.&#39; and &#39;@&#39;.
- Each emails[i] contains exactly one &#39;@&#39; character.
- All local and domain names are non-empty.
- Local names do not start with a &#39;+&#39; character.
- Domain names end with the &quot;.com&quot; suffix.
- Domain names must contain at least one character before &quot;.com&quot; suffix.

## Solution

Reference implementation from [solution.py on GitHub](https://github.com/wislertt/leetcode-py/blob/main/leetcode/unique_email_addresses/solution.py), full suite in [test_solution.py](https://github.com/wislertt/leetcode-py/blob/main/leetcode/unique_email_addresses/test_solution.py):

```python
class Solution:
    # Time: O(n * m) where n = len(emails), m = avg email length
    # Space: O(n * m)
    def num_unique_emails(self, emails: list[str]) -> int:
        seen: set[str] = set()
        for email in emails:
            local, domain = email.split("@")
            local = local.split("+")[0].replace(".", "")
            seen.add(f"{local}@{domain}")
        return len(seen)
```
